# 应龙大模型推理平台页面设计与前端开发规范 V4

## 0. V4 修订说明

本版依据 `ui_style_preview-V4-亚楠修改.html` 的可见规范说明整理，并在 V3 基础上进行精简。

- 保留：色彩、字体、关键尺寸、组件行为、状态语义、桌面端布局规则和导航映射。
- 补充：文字四级色、DIN 数字字体、下拉菜单、分页跳转、条形图、代码片段等规范。
- 精简：删除重复说明、示例业务文案、ASCII 布局图和大部分实现类名。
- 校正：辅助色、表格字号、H1 字重及最小字号统一以 HTML V4 描述为准。
- 布局调整：产品定位为桌面端 B 类管理平台，取消独立全局顶栏和层级导航；用户入口移至左侧导航底部。

---

## 1. 项目定位与设计目标

应龙大模型推理平台面向企业级 AI 算力调度、模型管理、在线推理和批处理任务。

- 在高数据密度下保持清晰的信息层级。
- 统一导航、表格、弹窗和状态反馈。
- 优先展示运行状态、资源风险和待办事项，减少无业务含义的装饰。

## 2. 页面设计与 UI 规范

### 2.1 色彩体系

| 类型 | 色值 | 用途 |
| :--- | :--- | :--- |
| 主品牌色 | `#266EFF` | 选中态、主按钮、高优先级聚焦 |
| 决策辅助色 | `Amber-500` | 申请、测算等关键决策操作 |
| 画布背景 | `Slate-50 / Slate-100` | 页面背景、弱分区 |
| 表面色 | `#FFFFFF` | 卡片、表格、弹窗、抽屉 |
| 信息 | `Sky-600` | 提示、排队、试用状态 |
| 成功 | `Emerald-600` | 健康、完成、校验通过 |
| 警告 | `Amber-600` | 资源紧张、阈值预警 |
| 错误 | `Rose-600` | 故障、拒绝、危险操作 |

文字颜色统一使用四级灰阶：

| 层级 | 色值 | 用途 |
| :--- | :--- | :--- |
| 一级 | `Slate-900` | 页面标题、KPI 主数值 |
| 二级 | `Slate-800` | 卡片和小节标题 |
| 三级 | `Slate-700` | 正文、表格、表单文字 |
| 四级 | `Slate-500` | 说明、时间戳、占位符 |

禁止使用纯黑正文或自定义灰度。禁用态可使用 `Slate-400`。

### 2.2 字体与文字

- 中文使用系统无衬线字体：`Segoe UI`、`PingFang SC`、`Microsoft YaHei` 等，不额外加载 Web 中文字体。
- KPI、监控数据、时间戳和分页码使用 DIN 数字字体，并启用等宽数字。

| 层级 | 字号 / 行高 / 字重 | 用途 |
| :--- | :--- | :--- |
| H1 | 20px / 28px / 700 | 页面标题 |
| H2 | 16px / 24px / 600 | 卡片、模块标题 |
| Body | 14px / 22px / 400 | 正文、表格、表单 |
| Caption | 12px / 18px / 400 | 说明、状态、时间戳 |

全站最小字号为 12px；按钮、标签和状态胶囊文字不得换行。

### 2.3 容器与圆角

- 卡片和弹窗使用白色表面、1px 浅灰边框和轻量阴影。
- 外层容器圆角为 8px 或 12px；按钮、输入框为 6px；状态胶囊为全圆角。
- 内层圆角应小于外层圆角，避免层级混乱。

### 2.4 列表、搜索与筛选

#### 2.4.1 基础列表

- 固定数据列表可不设置顶部工具栏。
- 表头使用 12px；表体统一使用 14px / 22px / `Slate-700`。
- 使用浅色行分割线，并提供清晰的行悬停反馈。

#### 2.4.2 搜索与筛选

- 搜索框包含搜索图标和清除入口，并显示匹配结果数量。
- 多维筛选按“搜索—筛选项—已选条件—重置”排列。
- 已生效条件使用可移除 Chip；多选时显示数量及批量操作。

#### 2.4.3 分页

- 同时显示记录区间、总数、每页条数、页码和手动跳转。
- 每页条数提供 10、20、50 三档；当前页使用品牌蓝高亮。
- 跳转页码必须限制在有效范围内。

### 2.5 弹窗与确认

- 弹窗由 Header、Body、Footer 构成；内容区滚动，头部和底部保持可见。
- 普通弹窗宽度不超过 672px，复杂授权类弹窗可扩展至 900px。
- Footer 操作右对齐，取消按钮在左，主操作在最右侧。
- 销毁、排空等高风险操作必须说明影响，并要求输入资源名称确认。
- 局部轻量操作使用触发按钮附近的 Popconfirm，点击外部关闭。

### 2.6 图表

- 时序图使用直折线，不使用平滑曲线。
- 多图并排时保持时间轴一致；双图采用 1:1 布局并联动 Crosshair。
- 图例可控制系列显隐；阈值线和基线需明确命名。
- 图例、坐标轴和注释不小于 12px，数值使用 DIN 字体。
- 横向条形图适合多类目对比，重点项使用品牌蓝，其余项弱化。
- 纵向柱状图单图不超过 3 个系列；超过时改用横向条形图或表格。

### 2.7 指标与功能卡片

- 卡片标题 16px，正文 14px，说明文字 12px；KPI 数值使用 DIN 字体。
- KPI 卡片：图标、数值、单位和趋势状态。
- 单操作卡片：图标、标题、简介和一个主要入口。
- 多操作卡片：图标、状态、说明及主次操作，避免堆叠过多按钮。

### 2.8 应用框架

平台采用“左侧导航 + 页面标题区 + 主内容区”的桌面端结构，不设置独立全局顶栏。本规范不覆盖移动端布局。

#### 2.8.1 左侧导航

- 标准展开宽度为 224px，可折叠为 64px 图标栏。
- 品牌区使用标准 Logo，不增加底色、圆角或投影。
- 导航按工作台、算力调度、模型管理、资源与运维分组。
- 激活项使用品牌蓝和浅蓝背景，并设置 `aria-current="page"`。
- 导航菜单独立滚动；用户区固定在侧栏底部，不随菜单滚动。
- 展开态显示头像、用户名、角色和菜单箭头；折叠态仅显示头像，点击后向右展开用户菜单。
- 用户菜单承载个人信息、账号设置和退出登录等操作。

#### 2.8.2 页面标题与操作区

- 每页仅有一个 H1，作为当前页面的主要位置标识，可附一行简短说明。
- 当前模块和页面位置通过侧栏分组及激活态表达，不重复设置层级导航。
- 页面操作位于标题右侧，按“范围信息—次要操作—主操作”排列。
- 搜索、刷新、导出和业务筛选均放入当前页面的操作区。
- 同一区域原则上只保留一个主按钮；无操作时不显示空工具栏。
- 图标按钮需提供可访问名称，控件必须保留键盘焦点状态。

### 2.9 消息与状态反馈

- 消息统一分为 Info、Success、Warning、Error 四级，并使用对应语义色和图标。
- 页面或区域级信息使用 Banner；短时全局反馈使用 Toast。
- 表单错误紧邻字段显示，并同步高亮输入框。
- 表格状态使用单行 Badge，不得只依靠颜色表达状态。

### 2.10 图标与 Logo

- 统一使用 Lucide 线框图标，禁止使用 Emoji 或混用其他图标库。
- 14px 用于行内操作；16px 用于导航；20px 用于模块标题；24px 用于 KPI 或缺省展示。
- 图文同行时保持居中和固定间距，图标不得被文字挤压。
- 平台 Logo 使用 `/doc/logo/icon_01.svg`；模型 Logo 从 `/model-icon/` 或 `/icon/` 引用，失败时回退为首字徽章。

### 2.11 时间筛选

#### 2.11.1 快捷时间段

- 用于看板和实时监控，选项为：实时、15m、1h、24h、7d、30d、自定义。
- 选中项使用品牌蓝；“自定义”打开绝对时间 Popover。

#### 2.11.2 精确时间段

- 用于日志、追踪和审计，精确到秒。
- 支持常用预设、双月日历、起止时间输入、重置和确认。
- 开始时间不得晚于结束时间；跨度超过数据保存期限时禁止提交。
- 时间控件文字为 14px，日历文字不小于 12px。

### 2.12 按钮与表单

- 按钮分为主按钮、决策按钮、次按钮、线框按钮、危险按钮和禁用态。
- 按钮横向内边距约为纵向内边距的 2 倍，并提供清晰的悬停和焦点反馈。
- 表单标签、输入内容和菜单项统一使用 14px。
- 下拉菜单项高度 32px；Hover 使用浅灰背景，已选项使用品牌蓝和勾选图标。
- 表单校验信息应紧邻对应字段。

### 2.13 代码片段

- 用于 cURL、Python 等调用示例和 stdout 日志。
- 显示示例名称或语言，并提供复制操作。
